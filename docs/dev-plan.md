# План разработки MVP

## 1. Назначение

Общий план итерации разработки MVP. Задачи, файлы и сроки по исполнителям — в планах недель из раздела 2.

Итерация MVP по графику проекта — **31 октября — 4 декабря 2026**: 31 октября — 8 ноября ушли на подготовку (аналитика, репозиторий, CI, моки), разработка идёт **9 ноября — 4 декабря**. Даты предварительные: при отставании переносятся задачи с приоритетом П2, а не конец итерации.

## 4. Ключевые зависимости

- **Недели разработки 1–3:** сначала согласуются контракт ядра на эндпоинты недели (Кирилл) и миграции таблиц недели (Денис). Порядок согласования и ревью — [plan-week1.md](plan-week1.md), раздел 8.
- **До 15 ноября:** `notifications.md` и таблица правил формата полей (Дима) — без них нет уведомлений и валидации на неделе 2.
- **Неделя 4:** команда сверяет остаток разработки с планом недели 3 и прогоняет готовые сценарии. Бизнес-сценарии Егора дают основу для системных требований Димы, макетов и тестов следующей итерации.
- **Через всю итерацию:** сквозные тесты включаются по мере готовности ядра, а не в конце.

## 5. П2 и следующий этап

| Что | Статус |
|---|---|
| Архив, экспорт и новая заявка на основе отклонённой | П2. Реализация после обязательных прогонов при наличии резерва. Остаток переносится в план следующей итерации |
| Несколько вариантов услуги | Системная аналитика — неделя 4. Реализация — после обязательных прогонов и утверждения контракта, при наличии резерва |
| Мобильный клиент для просмотра заявок и уведомлений | Бизнес- и системная аналитика — неделя 4. Реализация через существующий API-шлюз — итерация 3 |
| Брокер сообщений (RabbitMQ) | Путь развития, в MVP не входит |
| Генерация печатных форм договоров и актов | Вне объёма ([scope.md](scope.md)) |

## 6. Готовность MVP к демонстрации (к 4 декабря)

- SC-01, SC-02 и SC-03 проходят в интерфейсе нужными ролями. Сквозные тесты зелёные на общей сборке `DEMO`, результаты доступны по [стратегии QA](qa/qa-strategy.md).
- Ключевые крайние случаи (сбой интеграции, нарушение SLA, отмена, доступ к чужим данным) покрыты тестами.
- Демонстрация на чистом стенде: `docker compose up`, сид, сквозной сценарий — два прогона подряд без правок кода.
- README с инструкцией запуска; [tz-coverage.md](tz-coverage.md) отражает итоговое состояние по задачам и критериям ТЗ.
