# Архив заявок и экспорт

## 1. Назначение

Документ описывает ключевую продуктовую возможность прототипа: **полная история заявки с документами и этапами доступна в любое время, в том числе после закрытия, с переключением между этапами и версиями, и может быть выгружена для анализа**.

Для клиента это ответ на вопрос «что именно и когда происходило с нашей заявкой, кто что решал и какие документы подписаны». Для оператора — материал для разбора сроков и отказов.

Документ — вход для:
- Кирилла — запросы, индексы, выгрузка;
- Дениса — эндпоинты и представления;
- Егора — экраны поиска и досье заявки;
- Салавата — тесты на права и объёмы.

Основа: [domain-model.md](domain-model.md), [api-contract.md](api-contract.md) §6.10, [nfr.md](nfr.md), [roles.md](../business/roles.md) §6.5.

**Важно:** отдельного хранилища архива нет. «Архив» — это те же таблицы: заявка не удаляется никогда ([nfr.md](nfr.md), раздел 5), а признак `isArchived` вычисляется как `status ∈ {CLOSED, REJECTED, CANCELLED}`. Поэтому ничего не переносится и не теряется, а одни и те же эндпоинты работают и с активными, и с завершёнными заявками.

## 2. Пользователи и что им нужно

| Кто | Что ищет | Что видит |
|---|---|---|
| Представитель компании-клиента (в том числе аналитик) | Свои заявки за период, статусы, документы, причины отказов и отмен | Только заявки своей компании; без исполнителей, внутренних комментариев и SLA |
| Менеджер по продажам | Свои заявки, сроки прохождения, возвраты | Свои заявки целиком |
| Руководитель B2B | Все заявки, нарушения SLA, отказы, суммы | Всё |
| Координатор | Все заявки, паузы, просрочки | Всё |
| Системный администратор | — | Заявки не видит ([roles.md](../business/roles.md) §5.10) |

Ограничение видимости — та же единая политика доступа ядра, что и для активных заявок. Отдельных правил для архива нет, иначе появится второй путь к данным и второй шанс забыть проверку.

## 3. Досье заявки

Карточка завершённой заявки показывает то же, что и активной, плюс полную ретроспективу. Состав по разделам (разделы совпадают с матрицей видимости в [domain-model.md](domain-model.md), `request_member.sections`):

| Раздел | Содержание | Клиенту |
|---|---|---|
| Основное | Параметры заявки, адрес, скорость, компания, класс заявки, итоговый статус, уровень обязательств, даты ключевых событий | Да |
| Коммерческие условия | Варианты услуги (`service_offer`): выбранный и отклонённые, тариф, скидка, цена, тип договора | Да, без внутренних пометок |
| Маршрут и этапы | Все этапы всех версий маршрута: тип, исполнитель, статус, сроки, из-за каких правил этап появился (`requiredByRules`) | Да, без исполнителей |
| Решения | Решения согласующих: кто, когда, что решил, комментарий, снимок параметров на момент решения; в том числе отменённые решения (`superseded_at`) | Нет |
| Документы | Вложения с версиями: договор, акт, протокол разногласий; хеш, размер, кто и когда загрузил | Да, свои документы |
| Версии заявки | Снимки параметров (`request_revision`) с причиной изменения: отправка, доработка, пересборка маршрута, повторная ТВ | Да |
| История | `audit_log`: кто, что, когда, из какого статуса в какой, с каким комментарием | Да, в клиентской версии |
| SLA | Таймеры, нарушения, журнал пауз, время по SLA и календарное | Нет |
| Отмена | Инициатор, способ, уровень, причина, сумма затрат с расшифровкой, кто подтвердил | Да |

### 3.1. Переключение между этапами и версиями

Досье устроено так, чтобы можно было смотреть заявку «как она выглядела» в нужный момент:

- **По этапам.** Выбор этапа показывает связанные с ним решения, комментарии, вложения и отрезок истории. Этапы сгруппированы по версиям маршрута, отменённые и замещённые показываются с пометкой, а не скрываются.
- **По версиям заявки.** Выбор ревизии показывает параметры на тот момент и отличия от предыдущей ревизии (какие поля изменились, кто изменил, по какой причине).
- **По версиям документа.** У вложения видны все версии, текущая помечена; `supersedes_id` связывает их в цепочку.
- **Цепочка заявок.** Если заявка создана на основе отклонённой, показана ссылка на исходную (`parent_request_id`) и на дочерние — чтобы история клиента не рвалась на отказе по ТВ (EC-01).

Всё это уже хранится в модели: ничего не восстанавливается вычислениями по аудиту, кроме отрезков истории.

## 4. Поиск и фильтры

```
GET /api/v1/archive/requests?status=CLOSED&closedFrom=2026-01-01&segment=STRATEGIC&page=0&size=20&sort=closedAt,desc
```

Фильтруем и сортируем **только по колонкам**. Поля из JSONB в фильтрах запрещены — попытка даёт `422` ([api-contract.md](api-contract.md) §2.1).

| Параметр | Тип | Колонка |
|---|---|---|
| `q` | строка | Полнотекстовый поиск (раздел 4.1) |
| `number` | строка | `request.number` |
| `companyId` | UUID | `request.company_id` (для клиента подставляется принудительно) |
| `status` | список | `request.status` |
| `archived` | boolean | `status ∈ {CLOSED, REJECTED, CANCELLED}` |
| `requestClass` | `STANDARD` / `EXTENDED` / `LARGE` | `request.request_class` |
| `segment` | список | `request.segment` |
| `address` | подстрока | `request.address` |
| `speedFrom`, `speedTo` | число | `service_offer.speed_mbps` выбранного варианта |
| `tariffType`, `contractType` | перечисление | `service_offer.*` |
| `techResult` | перечисление | `request.tech_result` |
| `capexFrom`, `capexTo` | число | `request.capex` |
| `isGovCustomer`, `hasDebt` | boolean | `request.is_gov_customer`, `debt_amount > 0` |
| `managerId`, `assigneeId` | UUID | `request.manager_id`, `request_stage.assignee_id` |
| `createdFrom`, `createdTo` | дата | `request.created_at` |
| `submittedFrom`, `submittedTo` | дата | `request.submitted_at` |
| `closedFrom`, `closedTo` | дата | `request.closed_at` |
| `slaBreached` | boolean | Есть этап с `breached_at` |
| `hadRework` | boolean | Есть решение `RETURN` |
| `cancelInitiator`, `cancelMethod`, `cancelReason` | перечисление | `cancellation_request.*` |
| `rejectReason` | перечисление | Причина отказа |
| `approvalType` | список | Были ли согласования такого вида |
| `hasAttachmentKind` | перечисление | Есть вложение такого вида |

Сортировка: `createdAt`, `submittedAt`, `closedAt`, `number`, `capex`, длительность прохождения. По умолчанию — `createdAt,desc`.

### 4.1. Полнотекстовый поиск

Параметр `q` ищет средствами PostgreSQL (`tsvector` с русской конфигурацией) по: номеру заявки, адресу, названию компании, комментариям, видимым пользователю, и именам файлов вложений.

- Поисковый вектор хранится генерируемой колонкой `request.search_vector` с индексом GIN и обновляется триггером при изменении связанных данных.
- Внутренние комментарии не попадают в результаты для клиента: поиск идёт по двум векторам — общему и внутреннему, второй доступен только сотрудникам оператора.
- Полнотекстовый поиск — **не** замена фильтрам: он ищет по тексту, отбор по параметрам идёт колонками.

## 5. Аналитические показатели

Вычисляются запросом по уже имеющимся данным, отдельных таблиц-агрегатов в MVP нет.

| Показатель | Как считается |
|---|---|
| Срок прохождения заявки | `closed_at − submitted_at` (календарный) и сумма времени по SLA |
| Время на этапе | По таймеру этапа: время по SLA и календарное |
| Число возвратов на доработку | Число решений `RETURN` по заявке |
| Доля отказов по ТВ | Заявки с `tech_result = NONE` ко всем с результатом ТВ |
| Доля нарушений SLA | Этапы с `breached_at` ко всем завершённым этапам |
| Суммарная пауза | Сумма `sla_pause` по заявке, с разбивкой по причинам |
| Узкое место | Среднее время по типам этапов |
| Причины отмен | Группировка `cancellation_request.reason_code` по уровню и инициатору |
| Отклонённые варианты услуги | `service_offer` со статусом `DECLINED` — что клиентам предлагали и что они не выбрали |

Последний показатель — причина, по которой невыбранные варианты не удаляются ([domain-model.md](domain-model.md), `service_offer`).

## 6. Экспорт

Экспорт асинхронный, чтобы длинная выгрузка не держала HTTP-запрос.

```
POST /api/v1/exports/requests     { "format": "CSV", "filters": { ... } }   → 202 { "id": "..." }
GET  /api/v1/exports/{id}                                                   → статус и ссылка
```

| Формат | Что выгружается | Кому |
|---|---|---|
| `CSV` | Список заявок по текущим фильтрам: по строке на заявку, поля из раздела 4 плюс показатели раздела 5 | Всем, у кого есть доступ к поиску |
| `PDF` | Досье одной заявки: параметры, маршрут, решения, список документов, история | Всем, у кого есть доступ к заявке |

Правила:
1. **Экспорт никогда не выходит за права пользователя.** Фильтры применяются поверх политики доступа: клиент выгружает только свою компанию, и в его выгрузке нет исполнителей, внутренних комментариев и SLA.
2. Лимиты: 50 000 строк, один одновременный экспорт на пользователя ([nfr.md](nfr.md), раздел 7).
3. Каждый запрос экспорта и каждое скачивание результата пишутся в `audit_log` с составом фильтров и числом строк. Это главный канал утечки, поэтому он под аудитом.
4. Файл результата живёт 24 часа, затем удаляется фоновой задачей. Ссылка одноразовая и привязана к пользователю.
5. CSV — UTF-8 с BOM и разделителем `;`, чтобы Excel открывал его без шагов импорта; даты в ISO 8601; суммы строкой с двумя знаками.
6. Готовность приходит событием `EXPORT_READY`.
7. Выгрузка читается курсором (`fetchSize`), а не целиком в память.

## 7. Индексы

Дополняют список в [domain-model.md](domain-model.md), раздел 6.

| Индекс | Для чего |
|---|---|
| `request(company_id, created_at DESC)` | Список и архив клиента |
| `request(company_id, status, closed_at DESC)` | Фильтр по статусу и периоду закрытия |
| `request(manager_id, status)` | Заявки менеджера |
| `request(request_class, closed_at)` | Аналитика по классам |
| `request USING GIN (search_vector)` | Полнотекстовый поиск |
| `request_stage(request_id, route_version, type)` | Сборка досье |
| `approval_decision(stage_id, decided_at)` | Решения в досье |
| `audit_log(request_id, created_at)` | История заявки |
| `sla_pause(timer_id, started_at)` | Журнал пауз и суммарные паузы |
| `attachment(request_id, kind, version_no DESC)` | Документы с версиями |

Проверка: на объёме из [nfr.md](nfr.md) (20 000 заявок) поиск по архиву укладывается в 1 с p95; план запроса снимается `EXPLAIN ANALYZE` и прикладывается к задаче.

## 8. Чего здесь нет

| Что | Почему |
|---|---|
| Отдельное хранилище или холодный архив | Объёмы прототипа этого не требуют; заявки просто не удаляются |
| Конструктор отчётов | Хватает фиксированного набора фильтров и показателей |
| Графики и дашборды | За пределами объёма; данные выгружаются и строятся во внешнем инструменте |
| Выгрузка в XLSX | CSV достаточно; XLSX — при наличии времени |
| Подписанные PDF и штампы | Печатные формы и юридическая значимость вне границ прототипа |
| Доступ к архиву по API для внешних систем | Нет потребителя |

## 9. Тесты

| Тест | Что проверяет |
|---|---|
| Поиск по архиву от имени клиента | Видны только заявки своей компании (EC-16) |
| Поиск от имени удалённого сотрудника | Доступа нет (EC-17) |
| Клиентское представление досье | Нет исполнителей, внутренних комментариев, SLA |
| Досье закрытой заявки | Доступны все этапы, решения, версии и документы |
| Переключение версий заявки | Показаны отличия между ревизиями |
| Цепочка заявок после отказа по ТВ | Видна связь с исходной заявкой (EC-01) |
| Отменённые и замещённые этапы | Показаны с пометкой, а не скрыты |
| Фильтр по полю из JSONB | `422` |
| Экспорт клиентом | В файле только его компания и только разрешённые поля |
| Экспорт свыше лимита | `429` с `EXPORT_LIMIT_EXCEEDED` |
| Запись экспорта в аудит | Появляется запись с фильтрами и числом строк |
| Повторное скачивание по чужой ссылке | Отказ |
| Поиск на объёме 20 000 заявок | Укладывается в предел по времени |
| CSV в Excel | Кириллица не ломается (UTF-8 с BOM) |

## 10. Открытые вопросы

| № | Вопрос | Предложение | С кем решить |
|---|---|---|---|
| 1 | Видит ли клиент отклонённые варианты услуги в досье | Да: это его предложения, и это честнее | Дима, Егор |
| 2 | Нужен ли клиенту экспорт в PDF или достаточно просмотра | Нужен: это и есть ценность «досье заявки» | Дима, Егор |
| 3 | Срок жизни файла экспорта 24 часа | Да | Дима |
| 4 | Полнотекстовый поиск по комментариям — в MVP или позже | В MVP по заявке и адресу, по комментариям — если останется время | Дима, Кирилл |
| 5 | Нужен ли показатель «узкое место» в интерфейсе или только в выгрузке | В MVP только в выгрузке | Дима |
| 6 | Разделение прав «читать архив» и «выгружать» | В MVP не разделяем; в продукте выгрузка — отдельное право | Дима |
