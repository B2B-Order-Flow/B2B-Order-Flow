# Команда и роли

## Участники

| Участник | Роль | Зона ответственности |
|---|---|---|
| **Дима** | Тимлид + Системный аналитик | Доменная модель, статусы, маршрутизация, SLA, архитектура, координация, ревью |
| **Егор** | Бизнес-аналитик + Фронтендер | Бизнес-процессы, роли, сценарии, UI-требования, веб-панель оператора, клиентские сценарии |
| **Денис** | Бэкендер (API & BFF, схема БД) | API Gateway (FastAPI), DTO, валидация (Pydantic), внешний контракт (OpenAPI, единый формат ошибок), WebSockets (реалтайм-уведомления); схема БД ядра (миграции Flyway на SQL, справочники, индексы, права на таблицы); сид-скрипт демо-данных через API; ревью API-части кода ядра |
| **Кирилл** | Бэкендер (Доменное ядро) | Транзакционное ядро (Java 21 / Spring Boot), внутренний контракт ядра (OpenAPI), доменная логика, сущности JPA и доступ к данным, движок маршрутизации, SLA, история изменений, документы, интеграции с mock-сервисами (Integration Gateway) |
| **Салават** | DevOps + QA | Контейнеризация (Docker, Docker Compose), роли БД (скрипт инициализации, в том числе `backup_ro`), бэкап, CI/CD (GitHub Actions), mock-сервисы, QA-стратегия, интеграционные и E2E-тесты |

## Стек по ролям

### Дима
- **Документация и аналитика:** Markdown, Mermaid, UML-диаграммы.
- **Проектирование:** Спецификации бизнес-логики, FSM (конечные автоматы переходов статусов), архитектурный надзор.

### Егор
- **Аналитика:** Бизнес-процессы, сценарии (SC-00...SC-03), требования к интерфейсу.
- **Frontend:** React, Vite, TanStack Query, React Router, UI-библиотека (Tailwind / MUI), React Testing Library.

### Денис (API & BFF)
- **Язык / Фреймворк:** Python 3.12+, FastAPI, Uvicorn.
- **Валидация / Схемы:** Pydantic v2.
- **Асинхронность:** WebSockets для доставки реалтайм-уведомлений в UI.
- **Взаимодействие с ядром:** HTTP-клиент (`httpx`) с явными таймаутами, единый формат ошибок (RFC 9457), идемпотентность и версии для оптимистичной блокировки.
- **Документация API:** OpenAPI / Swagger UI.
- **БД и миграции:** PostgreSQL 16, Flyway (SQL-миграции, справочники, индексы, права на таблицы; роли БД создаёт DevOps) по соглашениям [domain-model.md](system/domain-model.md), раздел 8.
- **Тестирование:** pytest (unit-тесты BFF), контрактные тесты ядра по OpenAPI.

### Кирилл (Доменное ядро)
- **Язык / Фреймворк:** Java 21, Spring Boot 4.1.x, Spring Data JPA.
- **Доступ к данным:** Spring Data JPA поверх схемы из миграций (`ddl-auto=validate`); миграции пишет Денис, ревью — Кирилл.
- **Бизнес-логика:** Движок маршрутизации заявок, статусный автомат, контроль SLA (`@Scheduled` + `Clock`).
- **Безопасность и Аудит:** Spring Security + JWT, неизменяемый аудиторский лог (`AuditLog`), управление вложениями с версиями и формирование PDF-досье заявки.
- **Интеграции:** Spring RestClient, Spring Retry — вызовы mock CRM, биллинга и справочника клиентов вне транзакций.
- **Тестирование:** JUnit 5, Testcontainers.

### Салават (DevOps & QA)
- **Инфраструктура:** Docker, Docker Compose, GitHub Actions, развертывание на сервере.
- **Мониторинг и логирование:** Spring Actuator, SLF4J + Logback.
- **Тестирование:** JUnit 5, Testcontainers, Playwright (E2E), WireMock (моки внешних систем).
- **Контроль качества:** JaCoCo (покрытие кода тестами).

## Правила работы

- **Перекрёстное ревью:** Минимум 1 аппрув от ревьюера; кого звать — по таблице ревью в [plan-week1.md](plan-week1.md), раздел 8, и по ситуации. После аппрува автор вливает PR сам. PR ядра ревьюят Денис (контракт и поведение API) и Дима или Салават (код на Java); PR шлюза — Дима или Салават; миграции БД — Кирилл.
- **Архитектурный арбитраж:** Дима принимает финальное решение при спорных архитектурных или продуктовых вопросах.
- **Владение модулями:** Каждый участник несет персональную ответственность за свой компонент (Денис — шлюз и миграции БД, Кирилл — ядро, Егор — фронтенд, Салават — инфраструктура/тесты, Дима — аналитика/координация).
- **Ветки:** каждая задача разрабатывается в отдельной ветке; код-ревью обязательно. После начала разработки прямые коммиты в `main` запрещены, слияние только через pull request. Документы правятся так же, как код: короткая ветка `docs/…` от `dev` и PR в `dev`.
