# mocks

Моки внешних систем на WireMock: три контейнера (`mock-crm`, `mock-billing`, `mock-registry`), у каждого своя папка со стабами. Контракты и тестовые данные описаны в `docs/system/integrations.md` (ветка `docs`).

Владелец: Салават. Контракты согласовываются с Кириллом.

## Устройство

| Папка | Эндпоинт | Что отвечает |
|---|---|---|
| `crm/` | `GET /crm/v1/customers?inn=...` | Сегмент и закреплённый менеджер |
| `billing/` | `GET /billing/v1/accounts/{inn}/balance` | Задолженность |
| `registry/` | `GET /registry/v1/organizations?inn=...` | Реквизиты и признак госзаказчика |

В каждой папке `mappings/` хранит стабы (по одному файлу на тему, внутри массив `mappings`), `__files/` хранит тела ошибок. Стабы с `priority: 1` отвечают по конкретным ИНН, `default.json` с `priority: 10` отдаёт `404 NOT_FOUND` на любой другой ИНН. Так «Фантом» (`9977004455`) не найден ни в одной системе.

Моки возвращают в заголовке `X-Correlation-Id` то, что пришло в запросе (включён `--global-response-templating`). Ошибки приходят как `application/problem+json` с полями `code`, `correlationId`, `retryable`.

## Тестовые данные

Организации и ИНН совпадают с таблицей в `integrations.md`, раздел 5. Все ИНН и ОГРН с корректной контрольной суммой, иначе ядро не пропустило бы их к мокам. Отличия от документа:

| Что | В документе | Здесь |
|---|---|---|
| Временный сбой CRM (`503`, `503`, затем `200`) | `9999000019` | `9999000013` |
| Постоянный сбой CRM (`503`) | `9999000027` | `9999000020` |

Старые ИНН не проходят проверку контрольной суммы, ядро ответило бы `422` и до мока не дошло. Адреса организаций, кроме «Агрохолдинга Зари», выдуманы.

## Управляемые сбои (только CRM)

- `9999005565` («Таймаут»): ответ через 30 секунд, при таймауте ядра 2 секунды.
- `9999000013`: сценарий WireMock. Первые два запроса получают `503`, третий и все следующие `200`. Состояние общее на весь контейнер: перед каждым прогоном, который проверяет повторы, его нужно сбрасывать запросом `POST /__admin/scenarios/reset` (порт мока открывается через `infra/compose.mocks-ports.yaml`). Стабы сбоев загружены всегда, но вызываются только по своим ИНН.
- `9999000020`: всегда `503`.

## Как проверить руками

Из корня репозитория:

```
docker compose --env-file .env -f infra/compose.yaml -f infra/compose.mocks-ports.yaml up -d mock-crm mock-billing mock-registry
curl -i -H "X-Correlation-Id: test-1" "http://localhost:8081/crm/v1/customers?inn=7725012341"
curl -i http://localhost:8082/billing/v1/accounts/7844002230/balance
curl -i "http://localhost:8083/registry/v1/organizations?inn=7719003349"
curl -i "http://localhost:8083/registry/v1/organizations?inn=9977004455"
```

Ожидаемо: сегмент `LARGE`, долг `45000.00`, `isGovCustomer: true`, `404` с `NOT_FOUND`.

В PowerShell `curl` это алиас на `Invoke-WebRequest`, пишите `curl.exe`.

Папки смонтированы в контейнеры только для чтения. Если тест добавляет стабы через Admin API, передавайте `"persistent": false`.
